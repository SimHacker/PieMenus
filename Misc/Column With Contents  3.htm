Section 1 Gesture Commands

Gesture

Command

A Tap gesture involves a click of the left mouse button with no mouse pointer movement between pressing and releasing the button. For stylus-based input, this gesture involves a simple tap of the stylus. A tap gesture may have the following effect, depending on context:

  1. A tap gesture over a drawing element will select it.
  2. A tap gesture over empty space puts the application into ‘gesture mode’ to allow further gesture command input. This tap gesture must be performed before input will be recognized as a gesture vs. drawing input.

A PieMenu gesture involves depressing the left mouse button and holding it with no pointer movement for up to 500ms. For stylus-based input, this gesture involves a press-and-hold with the stylus. A PieMenu gesture will cause a context appropriate PieMenu to appear under the pointer.

A BandSelect/Segment gesture involves drawing a square/rectangle/diamond shape. It has two behaviors:

  1. If the gesture encompasses existing drawing elements, then it is a Band Select gesture and will cause the set of drawing elements contained within the gesture to be selected.
  2. If the gesture does not encompass any existing drawing elements, then it is the Segment gesture, and will cause a new, empty segment to be created.

A Delete gesture involves drawing a scribble, similar to that seen here. The Delete gesture will cause the deletion of all currently selected drawing elements.

A Zoom gesture involves drawing a circle/oval shape. This will cause the zoom level of the view to be controllable by a subsequent dragging gesture (press, hold and move). A drag toward the top of the screen will zoom outward, while a drag toward the bottom of the screen will zoom inward.

A Scroll gesture involves drawing a line. This will cause the view scrolling to be controllable by a subsequent dragging gesture (press, hold and move). The view can be ‘dragged’ in the desired direction to cause the scroll. A final click ends the scrolling

 

Section 2 Pie Menus

Navigating Pie Menus: A pie menu can be navigated in two ways: with out without pressing the mouse/stylus button. Initially, a ‘click-move-click’ action may be the simplest to learn. Once the menu is called via the press-and-hold gesture, release the button, move the pointer, and click on the menu item of choice. With practice, a ‘press-move-release’ action is quicker and more efficient. Once the menu appears via the gesture, move the pointer to the item of choice and release the button. Navigating these menus becomes very natural, with a little initial practice. For more information, see http://www.art.net/~hopkins/Don/piemenus/ .

Context Sensitive Pie Menus: The following chart specifies which pie menus will appear under certain conditions.

 

Pie Menu

Context

This pie menu appears under normal circumstances – i.e. when called from outside of any segments and no drawing elements are currently selected. The functionality offered by each menu item is equivalent to their drop down menu counterparts.

This pie menu appears whenever a drawing element is selected, whether inside or outside of a segment. The Segment menu allows the creation of a segment around the selected drawing element. The Recognizer menu provides access to recognition functionality.

This pie menu appears when called from with an unshared segment. The Sharing menu allows the current segment to be shared with others or attached to a remotely shared segment. The Unsegment menu removes the current segment.

This pie menu appears when called from within a shared segment. The Sharing menu allows the current segment to be unshared or disconnected from the current synchronous sharing session.
