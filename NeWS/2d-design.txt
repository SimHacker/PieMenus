2D/3D Open Look Componants

* The Problem
    The NeWS Toolkit Open Look componants are drawn in a trendy "3D"
    style using five different brightness values to represent light
    and dark shading of beveled edges. This effect is unusable on a
    black and white display when gray values are approxomated by
    stipple patterns. So in order to make it usable in two colors
    (i.e. black and white), the toolkit must be taught to draw the
    classic "2D" style Open Look.

* The Model
    The design is very simple: it is to insert "if" and "ifelse"
    conditionals into appropriate places in the painting code, to
    switch between 2D and 3D drawing procedures. A componant is
    painted in 2D or 3D according to the value of a variable, called
    "3D?". If 3D? is true, the componant is rendered in five color 3D.
    Otherwise it's rendered in two color 2D. This approach of having
    conditionals in the code is necessary in order to support multiple
    heads and canvases of differing depths.

* The Interface
    The interface consists of a class variable called "/3D?" (which
    may actually be method), the method "/set3D", the color class
    variables "2DFG" and "2DBG", and the utility functions
    "ForegroundColor" and "BackgroundColor", all defined in
    ClassDrawable.  The Open Look painting code (called by /Paint)
    uses "3D?" to decide whether to render in 2D or 3D.  The size of
    each Open Look componant is exactly the same in 2D and 3D.  Idealy
    the drawing code is factored to share as much as possible between
    2D and 3D. The "3D?" variable only effects a componant's look, it
    does not change its layout, size, or behavior.

    Defined in ClassDrawable:

    /3D?		% - => bool
	This variable (or method) controls the dimensionality of Open
        Look objects. If it's true, they are drawn in 3D, using the 5
        colors, FG BG BG0 BG2 and BG3. If it's false, they are drawn
        in 2D, using the 2 colors, 2DFG and 2DBG.

    /set3D		% bool => -
	Sets the dimensionality to 3D if bool is true, or 2D if false.
	This method does not cause the object to repaint, but it does
	invalidate objects of the following classes (because they have
        cached drawing information that needs to be updated):
	    ClassButtons ClassMenuButtons ClassMenu
	    ClassVScrollbar ClassHScrollbar

    /Color		% - => bool
	Method that returns true if the drawable is color.
	In ClassDrawable, it is defined as "framebuffer /Color get".
	(Maybe it should be a SubClassResponsibility?)
	In ClassCanvas, it is overridden by the /Color key of the canvas
	magic dictionary, which returns true if the canvas is color. 
	In ClassRegion, it is defined as "Parent /Color get".

    /2DBG		% - => color
    	White.

    /2DFG		% - => color
    	Black.

    /BackgroundColor	% - => color
    	BG or 2DBG, according to the dimensionality.
	You are encouraged to use BackgroundColor instead of BG,
	if you want text to be legible in monochrome.

    /ForegroundColor	% - => color
	FG or 2DFG, according to the dimensionality.
	You are encouraged to use this ForegroundColor of FG,
	if you want text to be legible in monochrome.

    /Paint2DBox % x y w h bold? => -
	Paint a 2D box using the 2DFG and 2DBG colors, whose bounding
        box is defined by the arguments. When down? is true the box
        appears stroked with a double thick line. 

* The Impact
    The 3D drawing code must be identified and conditionalized.  This
    effects code that uses specific colors, Paint3DBox, or the 3D
    olglyph characters.

    Example:

    /PaintSlider { % - => -
	GraphicFont setfont
	SliderX 10 add SliderY
	2 copy moveto
	3D? {
	    BG setcolor //VERT_SLIDER_CONTROL_FILL show
	    2 copy moveto
	    BG0 setcolor //VERT_SLIDER_CONTROL_UL show
	    moveto
	    BG3 setcolor //VERT_SLIDER_CONTROL_LR show
	    SliderHilited? {
		SliderX 13 add SliderY
		2 copy moveto
		BG3 setcolor //DIMPLE_UL show
		moveto
		BG0 setcolor //DIMPLE_LR show
	    } if
	} {
	    2DBG setcolor
	      //VERT_SLIDER_CONTROL_FILL show
	    2DFG setcolor
	      moveto
	      //VERT_SLIDER_CONTROL_OUTLINE show
	} ifelse
    } def

* The Performance
    There will be an impact on speed and size, because of the extra
    drawing code and the extra tests at run time. The 2D drawing is 
    faster than the 3D drawing since it uses fewer colors and glyphs,
    but both the 2D code and the 3D code must be loaded and active at
    once in order to have 2D and 3D displayed at the same time, as 
    is required by screens with multiple heads or plane depths.

* Design Choices

** Short term goals
    Open Look 2D and 3D controls are the exact same size, so control
    panels do not have to be arranged differently.

    Display 2D and 3D at the same time (multi head, multi plane,
    testing 2D on color).

    Choose between 2D and 3D at for all subsequently created objects,
    by sending a "/set3D" message to ClassDrawable.

    Change a particular object between 2D and 3D at run time by
    sending it a "/set3D" message.

** Long term holy grails
    Clean up painting code.
    Scalability.
    Printability.

** Dynamic Behavior
    How well do objects deal with "3D?" changing?  If you tell a
    particular instance to set its dimensionality, it will work,
    because classes that cache state based on /3D? can invalidate it
    by overriding /set3D. But if you tell a whole *class* (i.e.
    ClassDrawable) to set its dimensionality, controls of that class
    that were previously created may be put into a strange state. In
    most cases [if /3D? is not promoted to an instance variable],
    pre-existing controls will still correctly repaint in the new
    dimensionality next time they are damaged. But the more
    complicated controls that cache strings and colors will not update
    properly until they are invalidated (which may be impossible for
    the user to cause to happen). Some controls cache some values
    based on 3D? at validation time, but calculate others at paint
    time, so they will paint in a strange mixture of 2D/3D, but at
    least they will not crash if /3D? is changed out from underneath
    them.
